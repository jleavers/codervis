## Goal

Make the Gemini Code Assist widget compatible with Antigravity CLI (`agy`)
1.0.6 while preserving codervis's existing security boundary:

- Read only the file-backed OAuth token under the mounted `~/.gemini` tree.
- Do not expose the host Linux keyring, D-Bus session, or Secret Service to
  Docker.
- Prefer the quota endpoint used by `agy` 1.0.6.
- Retain compatibility with the legacy quota endpoint while it remains
  available.

## Authentication Boundary

The Gemini client continues to read:

```text
~/.gemini/antigravity-cli/antigravity-oauth-token
```

or the explicit `GEMINI_TOKEN_FILE` override. The accepted JSON forms remain:

```json
{"token": {"access_token": "..."}}
```

and:

```json
{"access_token": "..."}
```

Keyring-only authentication is deliberately unsupported. If `agy` stores no
file-backed token, codervis reports the Gemini source as unavailable and the
health endpoint reports that Gemini credentials are absent.

## Quota Request Flow

After `loadCodeAssist` discovers the companion project, the client:

1. Calls `v1internal:retrieveUserQuotaSummary` with the discovered project.
2. Parses the summary response into Pro and Flash windows.
3. Falls back to `v1internal:retrieveUserQuota` only when the summary method is
   unavailable because Google returns HTTP 404 or 405.
4. Treats all other summary errors as failures rather than masking
   authentication, authorization, network, or malformed-response problems.

This narrow fallback avoids issuing a second request for invalid credentials
or upstream outages while retaining compatibility with deployments where the
new method is not exposed.

## Schema Handling

The existing legacy response uses model-oriented buckets with fields such as:

- `modelId`
- `tokenType`
- `remainingFraction`
- `remainingAmount`
- `resetTime`

The summary response uses display-oriented buckets with fields such as:

- `bucketId`
- `displayName`
- `remainingFraction`
- `remainingAmount`
- `resetTime`

The parser normalizes both forms into the current internal bucket shape.
Classification uses all available identity text (`modelId`, `bucketId`, and
`displayName`) and matches `pro` or `flash` case-insensitively. Alternate
snake_case field names remain accepted.

If multiple matching buckets exist, codervis preserves its current behavior:
show the most constrained valid bucket. Detail text uses the most useful
available identity, preferring model ID, then display name, then bucket ID.

Malformed individual buckets are skipped. If neither a usable Pro nor Flash
bucket remains, the client raises `GeminiLiveQuotaError`, causing the widget to
render unavailable rather than inventing usage.

## Error Handling

The existing contract remains unchanged:

- Token read or parse failures become `GeminiLiveQuotaError`.
- Authentication, authorization, network, and unexpected HTTP failures become
  `GeminiLiveQuotaError`.
- Invalid JSON or response shapes become `GeminiLiveQuotaError`.
- Only HTTP 404 and 405 from `retrieveUserQuotaSummary` trigger the legacy
  endpoint fallback.
- No OAuth refresh or login behavior is added.
- OAuth tokens are never logged or included in errors.

## Health And Configuration

`gemini_credentials_present` continues to mean that the configured token file
exists. No keyring detection is attempted.

The default read-only mount remains:

```text
${GEMINI_HOME:-~/.gemini}:/data/gemini:ro
```

No new Docker privileges, host sockets, environment secrets, or writable
credential mounts are introduced.

## Documentation

Update `README.md`, `.env.example`, and `CLAUDE.md` to state:

- codervis supports `agy` 1.0.6's file-backed Linux authentication path;
- keyring-only sessions are intentionally unsupported;
- `retrieveUserQuotaSummary` is preferred with a 404/405 fallback to
  `retrieveUserQuota`;
- running `agy` and confirming the token file exists is the setup validation
  sequence.

No Docker Compose behavior changes are required.

## Tests

Add focused tests before implementation for:

1. A summary response using `bucketId`, `displayName`, remaining fraction, and
   reset time.
2. Summary endpoint preference and request payload.
3. Legacy endpoint fallback after a summary HTTP 404.
4. No legacy fallback after summary HTTP 401 or a network failure.
5. Tolerance for snake_case summary fields and malformed unrelated buckets.
6. Existing legacy response behavior remaining intact.

Run the focused Gemini tests during the red-green cycle, then run the complete
pytest suite and Python compilation checks.

## Success Criteria

Compatibility can be claimed when:

- codervis successfully parses an `agy` 1.0.6-style quota summary response;
- legacy quota responses still work when the summary method is absent;
- keyring access is neither required nor exposed;
- all automated tests and compilation checks pass;
- the documented setup accurately describes the supported authentication
  boundary.
